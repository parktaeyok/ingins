# 게시판

회사소개 옆 펼침 버튼 → 게시판으로 이동합니다. PC와 모바일에서 같은 하위 메뉴를 사용합니다.

- `/board/`: 최신순 목록, 제목 검색, 10개씩 페이지 이동
- `/board/post/?id=게시글UUID`: 제목·작성자 공개, 열람 비밀번호 확인 후 본문 조회
- `/board/write/`: 로그인 후 작성
- `/board/write/?id=게시글UUID`: 본인 글 수정
- 삭제는 본인 글에서 확인창을 거쳐 실행합니다. 글은 일반 텍스트로 저장합니다.

## Supabase 설정

기존 회원가입과 같은 프로젝트 `ejwutsrpugxuexdquchu`를 사용합니다. 작성자는 등록 프로필이 있는 로그인 회원이어야 합니다. 비밀번호 검증과 본문 전달은 `/api/board/` 서버에서 처리하므로 Vercel Production 환경변수 `SUPABASE_SECRET_KEY`가 필요합니다. `SUPABASE_URL`이 비어 있으면 `NEXT_PUBLIC_SUPABASE_URL`을 사용합니다. 기존 아이디 로그인과 같은 서버 키이며 브라우저용 환경변수에 넣지 않습니다.

### 연결 오류 코드

- `BOARD_SECRET_MISSING`: 현재 배포의 서버에서 `SUPABASE_SECRET_KEY`를 찾지 못했습니다. Vercel **ingins → Settings → Environment Variables**에서 이름을 정확히 입력하고 **Production**을 선택해 저장한 뒤 새로 배포합니다. 다른 이름이나 Preview에만 등록한 값은 사용할 수 없습니다. 비밀번호 불일치 오류와는 다릅니다.
- `BOARD_URL_MISMATCH`: 서버 주소가 다른 프로젝트를 가리킵니다. 이 프로젝트 주소로 수정합니다.
- `BOARD_SECRET_FORMAT`: 공개 키나 예시 값이 서버 키에 들어 있습니다. 같은 프로젝트의 Secret key 또는 service_role 키를 서버에만 설정합니다.
- `BOARD_LOAD_*`, `BOARD_SET_PASSWORD_*`, `BOARD_LIMITER_*`: 해당 단계의 DB 오류 코드입니다. 서버 로그에는 단계와 코드만 남기고 키·본문·비밀번호는 남기지 않습니다.

1. SQL Editor에서 `select to_regclass('public.site_board_posts');`로 확인합니다.
2. 신규 설치라면 `supabase/setup-board.sql` 적용 후 `supabase/setup-board-password.sql`을 순서대로 최초 1회 적용합니다. 현재 프로젝트에는 두 SQL을 모두 적용했으므로 다시 실행하지 않습니다.
3. 환경변수와 회원가입 설정이 완료된 배포에서 목록 → 로그인 → 작성 → 상세 → 수정 → 삭제를 확인합니다.

2026-10-30 로그인된 Supabase SQL Editor에서 기본 게시판과 비밀번호 보호 업그레이드를 적용했습니다. 현재는 공개 메타데이터 조회만 허용하고 쓰기는 서버에서 처리합니다. `supabase/tests/board-password-rls.sql` 검증이 통과했습니다. 비회원·회원의 본문/해시 접근 차단, 직접 쓰기 차단, 서버 저장·수정·삭제, 11번째 비밀번호 시도 차단과 카운터 초기화를 확인했습니다. 기존 글 2개는 보존됐고 테스트 계정은 남아 있지 않습니다. 설치 SQL을 다시 실행하지 않습니다.

## 권한

목록에는 제목·작성자·날짜만 공개합니다. 본문과 비밀번호 해시는 비회원·회원·작성자 모두 DB API로 직접 조회할 수 없습니다. 브라우저의 직접 INSERT/UPDATE/DELETE도 차단하며 서버가 Auth 토큰으로 회원을 검증하고 작성자 UUID를 확인합니다. 열람은 작성자도 비밀번호를 입력해야 합니다. 열람 비밀번호를 아는 다른 회원에게 수정·삭제 권한이 생기지는 않습니다.

새 글에는 8~128자의 열람 비밀번호가 필수입니다. 비밀번호는 랜덤 salt를 사용하는 scrypt 해시로만 저장하며 원문을 저장하지 않습니다. 비밀번호와 본문을 URL·로그·localStorage에 남기지 않고 응답은 no-store로 처리합니다. 비밀번호 확인은 글·접속 IP의 HMAC 키별 10분 동안 10회로 DB에서 제한합니다. 올바르게 확인하면 해당 시도 카운터를 초기화합니다. 비밀번호를 틀리거나 시도 제한 저장소에 오류가 있으면 본문을 반환하지 않습니다.

기존 글 2개는 내용 그대로 보존하고 비밀번호 미설정 상태로 본문을 숨깁니다. 작성자가 상세 화면에서 최초 비밀번호를 설정한 뒤 열 수 있습니다. 설정된 비밀번호는 현재 비밀번호를 확인하고 수정 화면에서 바꿀 수 있으며 원문 복구 기능은 없습니다. 새로고침하거나 '다시 잠그기'를 누르면 다시 입력해야 합니다.

권한 검증은 현재 `supabase/tests/board-password-rls.sql`을 사용합니다. 이전 `board-rls.sql`은 비밀번호 도입 전 구조를 위한 이력입니다. 서버 API와 해시 검증은 `tests/board-access.test.mjs`에서 검증합니다.

관리자 회원관리·타인 글 관리, 첨부파일, 댓글은 이번 게시판 범위에 포함하지 않습니다. 회원 탈퇴 시 해당 계정의 글은 함께 삭제됩니다.
