# 회원가입 설정

`/signup/`에서 아이디·이름·이메일·비밀번호·전화번호·우편번호·기본 주소를 입력합니다. 회사명과 상세 주소는 선택입니다. 아이디는 영문 소문자로 시작하는 4~24자의 영문·숫자·밑줄이며 중복 확인과 DB의 유일성 제약으로 보호합니다. 로그인은 `/login/`에서 이메일로 진행합니다. 이메일 인증 후 `/account/`에서 등록 정보를 확인하고 로그아웃할 수 있습니다.

## 연결과 DB 적용

공개 연결용 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`를 배포 환경에 등록하고 빌드합니다. 비밀 키는 브라우저에 사용하지 않습니다. 기존 DB 구조를 유지하며 `supabase/setup-registration.sql`을 한 번 적용합니다. 등록용 두 테이블과 Auth 가입 트리거를 추가합니다. 기존 상담·회원·게시판 테이블이나 역할은 변경하지 않습니다.

현재 연결된 Supabase MCP의 DB 인증 오류(`28P01 password authentication failed`) 때문에 원격 적용·실제 DB 검증은 완료하지 못했습니다. 이 SQL은 적용 대기 상태입니다. 연결을 복구하거나 Supabase SQL Editor에서 적용한 뒤 중복 확인과 가입을 사용합니다. 실행 전 기존 테이블과 트리거 이름 충돌 여부를 확인합니다.

Supabase Auth에서 이메일 가입과 이메일 확인을 활성화하고, Site URL과 `/account/` 인증 리디렉션 주소를 실제 사이트에 맞춥니다. 로컬 미리보기는 `http://localhost:3130/account/`를 등록합니다. 비밀번호 재설정·전화번호 인증·주소 검색 API·회원 정보 수정은 이번 범위에 포함하지 않습니다. 전화번호와 주소는 입력받는 정보이며 본인 인증 결과가 아닙니다.

## 개인정보와 권한

전화번호·주소를 포함한 등록 정보는 `registration_profiles`에 저장하고 RLS로 본인만 조회합니다. 중복 확인용 `registration_handles`는 아이디 열만 공개하며 소유자 UUID에는 SELECT 권한을 주지 않습니다. 비밀번호는 Supabase Auth가 관리하며 자체 프로필 테이블에 저장하지 않습니다. 가입 중 이메일 인증 전 데이터를 원자적으로 저장하기 위해 Auth의 사용자 메타데이터를 거쳐 트리거로 저장합니다. 메타데이터를 관리자 권한 판단에 사용하지 않습니다.

최종 아이디 예약과 프로필 저장은 같은 Auth 가입 트랜잭션에서 실행됩니다. 미인증 계정도 아이디를 예약하므로 운영 시 미인증 계정 보관·정리 기준을 별도로 정해야 합니다. 회원 정보 삭제·탈퇴 요청은 개인정보처리방침의 연락처로 접수합니다. 실제 개인정보 보유기간과 인증 메일 수신·리디렉션은 운영 전에 확정·확인합니다.
