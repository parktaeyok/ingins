# 회원과 게시판 운영

## 화면

- `/auth/`: 이메일 회원가입, 로그인, 비밀번호 재설정 메일 요청
- `/account/`: 회원 정보·비밀번호 변경, 로그아웃
- `/board/`: 게시판 필터, 제목 검색, 페이지 이동; 관리자에게는 게시판 생성 폼 표시
- `/board/new/`: 로그인 회원의 글 작성
- `/board/[id]/`: 글 읽기; 작성자·관리자의 수정 및 삭제
- `/admin/members/`: 관리자의 회원 목록, 이용 중지와 재개

오른쪽 메뉴는 중간에 고정하며 각 하위 항목에 번호·화살표·테두리와 키보드 포커스 표시를 제공합니다. 메뉴가 길면 메뉴 영역 안에서 스크롤합니다. 작은 화면에서는 메뉴 버튼으로 엽니다.

## 연결

`NEXT_PUBLIC_SUPABASE_URL`과 `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`를 설정하고 빌드합니다. 공개 키만 사용합니다. 기존 상담 접수용 `SUPABASE_SECRET_KEY`는 회원·게시판 기능에 필요하지 않습니다.

Supabase Auth에서 이메일 제공자와 이메일 확인을 활성화합니다. 자동 확인을 켜면 이메일 소유권 검증이 생략되므로 관리자 이메일 자동 연결을 사용하는 이 구성에서는 반드시 이메일 확인을 유지합니다. 가입 화면은 이메일 인증을 요구하며 실제 프로젝트의 `mailer_autoconfirm=false`를 확인했습니다.

Auth의 URL Configuration에 실제 운영 주소를 Site URL로 지정하고 `/account/`를 포함하는 Redirect URL을 등록합니다. 로컬 테스트 시 `http://localhost:3110/account/`도 등록합니다. 인증·비밀번호 재설정 메일의 도착 여부와 리디렉션은 실제 받은 메일로 최종 확인합니다.

## 데이터와 권한

`ac_ingins` 프로젝트를 재개하고 원격 마이그레이션 `20261015225006_member_community_and_verified_admin`을 적용했습니다. `supabase/setup-member-community.sql`은 동일한 변경을 검토하기 위한 일회성 SQL 원본이며 이미 적용된 DB에 다시 실행하지 않습니다. 기존 회원 테이블의 username/full_name과 기존 데이터는 보존했습니다.

- 공개: 활성 게시판과 글 읽기
- 인증 회원: 자신의 프로필 읽기·수정, 회원용 게시판 글 작성, 본인 글 수정·삭제
- 중지 회원: 글 작성·수정·삭제 불가, 자기 상태 변경 불가
- 관리자: 회원 목록 및 이용 상태 변경, 게시판 생성, 공지 작성, 게시글 관리
- 역할·작성자·작성일 등은 클라이언트 UPDATE 권한에서 제외
- DB의 RLS와 API의 검증된 사용자 확인을 함께 적용
- 관리자 판정에는 사용자가 편집할 수 있는 user_metadata를 사용하지 않음

첫 관리자는 `taeyok@naver.com`으로 등록했습니다. 해당 주소의 가입·이메일 인증이 완료되면 DB가 관리자 역할을 연결합니다. 아직 관리자 계정의 비밀번호를 생성하거나 인증 메일을 대신 발송하지 않았습니다. 사용자 계정은 가입 화면에서 직접 만듭니다. 추가 관리자 지정은 DB에서 확인된 회원에게 별도로 수행합니다.

## 검증

`supabase/tests/community-rls.sql`은 트랜잭션 안에서 임시 데이터를 만들고 전부 롤백합니다. 이메일 인증 전후 관리자 연결, metadata 역할 위조 차단, 공개 읽기, 프로필 분리, 소유권, 공지 권한, 회원 중지와 관리자 기능을 검사합니다. 해당 테스트와 Supabase 보안 advisor 검사를 통과했습니다.

게시글은 일반 텍스트로 표시합니다. 파일 첨부·댓글·소셜 로그인·회원 자동 탈퇴는 이번 구현 범위에 포함하지 않습니다. 탈퇴와 개인정보 삭제는 개인정보처리방침의 연락처로 요청합니다.
